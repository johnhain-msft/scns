## SC-008 — "zero human turns serve as the labelling basis for more than one record" → MEASURED, CLOSED

**Result: zero violations.** 27 settled rows carry a turn binding; they occupy **27 distinct**
`(conversation_id, turn)` groups, so no group holds more than one record.

```

groups_total|27
```

### The first measurement was VACUOUS, and that is the finding

The obvious query — group by the `turn` COLUMN — returned a clean zero:

```
settled_rows_with_turn_binding|0
turns_shared_by_more_than_one_SETTLED_record|0
```

That zero means **nothing**. `turn` is NULL on **all 2059 rows**:

```
rows_with_turn_NOTNULL|0
rows_with_conversation_id_NOTNULL|1873
```

The turn is actually recorded inside `answer_source` (`transcript-oracle:turn-4`,
`followup:dispute:turn-4:conf-0.90`). Reporting the first zero as "SC-008 satisfied" would have been
an overclaim of exactly the kind this feature exists to remove: **a criterion passing because nothing
was looked at.**

### It also made a shipped FR-038 check UNREACHABLE

`detectSampleCaveats`'s duplicate-binding check keyed on `... AND turn IS NOT NULL`. Against live data
that predicate matches zero rows **always**, so the check could never fire — and its silence rendered
in John's report as *"no known open defect touches these records"*. A guard that cannot fire is worse
than no guard, because it manufactures reassurance.

RED first, seeding the PRODUCTION shape (turn column NULL, turn encoded in `answer_source`):

```
→ expected '' to match /#18|duplicate/i
 Test Files  1 failed (1)
      Tests  1 failed | 6 passed (7)
```

Fixed to read the turn wherever it actually lives (column when present, else parsed from
`answer_source`), with two negative controls that pin what is NOT a duplicate — different turns in one
conversation, and the same turn number in different conversations.

```
 Test Files  1 passed (1)
      Tests  7 passed (7)
```

Re-measured on a WAL-inclusive copy of the live corpus with the corrected check:

```
FR-034 — 3 record(s) in this sample carry no answer_source provenance (id 1824, 1825, 1826); …
```
— i.e. **no** duplicate-binding caveat, now for a reason that has been verified rather than assumed.

> Note this changes the earlier C7 claim "duplicate binding touches ZERO sample rows". The number is
> unchanged, but the earlier reading was produced by an unreachable query and was not evidence.
