**The live blast radius is one row.** It must not be reported as unblocking a backlog. Exactly one
terminal row in the whole store carries a non-decision verdict, and it is this one
(`files/t200-reachability.txt`):

```
=== 0dfe7c86-7f5a-4d0c-bfab-3d15e2f1a92e ===
  status        = rejected
  reviewVerdict = explain
  reviewReason  = "human:needs-explanation: I don't understand what 'field' as a new global tag would accomplish."
  machineReason = undefined
  createdAt     = 2026-04-21T06:10:20.932Z
  LANE          = backfill, rank 21 of 108
  priority      = 1.35
  why           = no decision of yours survives on this — 108 days since it was raised
  weeks at 2/week = 11
```

Three things this row settles that no fixture could:

1. **The defect was real and it happened to John.** That `reviewReason` is him asking a question on
   2026-04-21. The answer deleted the item, and it has not been asked about since.
2. **One predicate would not have been enough.** `machineReason = undefined`, so this row carries no
   SC-029 signature at all — `matchesCensusSignature` never sees it. It is restored **solely** by the
   backfill-filter half of the change. The companion's §3.1 ruling argued this from the matrix; this
   is the same conclusion from a live row.
3. **"Reachable" is not "in front of him".** Rank 21 of 108 at 2 slots/week is roughly 11 weeks out.
   Honest statement: the item is back **in the queue and reachable**, not back **on this week's
   packet**. Claiming otherwise would be the overclaim this evidence standard exists to prevent.

FR-041 rendering is unchanged: both pools already exceeded their caps before this change (9 > 5,
107 > 2) and both already disclose their denominators (`totalEscalated`, `totalUnexplained`). No
capped numerator is printed alone; no new disclosure obligation was created.

## 6. What this change does NOT do

- It does **not** alter `needs-human` classification. `isGateEscalated` consults
  `matchesCensusSignature` only when `escalationKindOf(s)` is `null`, which is never true for a
  `needs-human` row — demonstrated by the matrix, where the untouched `needs-human` row has
  `signature=true` in every column yet lands in `backfill`, never `escalated`. `repromote` and
  proposal triage read the same classification they did before.
- It does **not** widen to "any human prose". A `human:` reason with no `reviewVerdict` still counts
  as decided, matching `lastHumanDecisionAt` (`weekly-review.ts:186`). Pinned by the negative control
  *"still drops an item explained through the VERDICT-ABSENT seam"*.
- It does **not** create a pool nothing leaves. `approve` and `reject` drain both pools in all three
  statuses, pinned by four negative-control tests and re-measured in the matrix above.
- It does **not** amend an FR, flip a default, or write to the live store.
