## 4. The honest negative result — `65a914f4` did NOT move

```
=== 65a914f4-b229-4fde-874e-c46a44dd845f ===
backfill rank 107 of 107
  priority = 0.001691870023148148
  why      = this landed without a recorded reason

```

Unchanged from the T150 baseline, and this was **predicted in writing before the code was written**
(`003-T150-backfill-baseline-2026-08-06.md` §2.2), not discovered afterwards. The reason:

- It no longer carries the SC-029 signature — its `machineReason` is `machine:applied-and-verified: …`
  and `reviewVerdict: "approve"` stands — so the reserved lane correctly does not claim it.
- Its `reviewedAt` is `2026-08-05T23:30:30.590Z`, stamped by a **machine** status transition on
  2026-08-05, i.e. *before* this branch stopped machine writes from stamping it. FR-070 reads that
  timestamp as a real human decision because, from the file alone, it is indistinguishable from one.
  Repairing it would mean editing stored history to improve a ranking, which FR-071a and T149 both forbid.

**The fix is forward-only, and that is the correct behaviour, not a shortfall.** Any row the gate touches
from now on keeps its human review clock. Inventing a heuristic to retro-detect machine-written timestamps
would be exactly the "infer what he meant" that FR-051/SC-025 prohibit.

## 5. Behaviour changes a reviewer should look at deliberately

1. **`updateStatus` no longer stamps `reviewedAt` for `author: 'machine'`** (`suggestion-store.ts`).
   Widest-reaching change here. `weekly-session.ts` renders this field as when John reviewed an item and
   folds it into `assessEngagement`, which gates an autonomy raise — so before this, a quality-gate build
   attempt counted as evidence he was paying attention. The machine's write is still fully recorded in
   `updatedAt`, `machineReason`, `attemptCount` and `lastAttemptAt`; it is simply no longer recorded as a
   *review*. Pinned both ways (machine leaves it standing / human still stamps it).
2. **A `rejected` row with `qg-fail:*` and no verdict now routes to the reserved lane, not the backfill
   pool.** This changed one pre-existing test, `weekly-review.test.ts`'s "65a914f4 replay". Its underlying
   invariant — a wordless verdict is not an explanation — is unchanged and still asserted on a fixture
   that does not carry the signature; a second case now pins the new routing. The old assertion described
   the routing this task exists to change.
3. **`QG_FAIL_PREFIX` is now defined once** in `escalation.ts` and imported by `qg-mislabel-census.ts` and
   `qg-mislabel-repair.ts`, which each held their own copy. A census that stopped counting a shape the
   repair still rewrites would have failed silently — both sides working, only the number between them
   wrong.
4. **Not changed, deliberately**: the packet still emits `selectedEscalated + selectedPending +
   selectedBackfill` items against `budget`, so a full escalated lane yields 10 items for a budget of 5
   (measured live: 5 + 3 + 2). Pre-existing, out of scope, and *reducing* it would starve the ordinary
   pools — the failure T155 warns about. Flagged rather than silently altered.
