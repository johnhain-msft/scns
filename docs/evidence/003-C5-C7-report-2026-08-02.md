## 5. FR-037a is NOT SATISFIABLE AS WRITTEN — needs John's ruling

FR-037a requires a negative control proving "a small sample with a large apparent gap does **not**
yield a promotion — the verdict must still fail on the confidence bound". Measured against the
unmodified gate:

```
verdict(small n=5 v 5, means 0.12 vs 0.92, real variance): promote=true, LB +0.6860
verdict(zero-variance 5 v 5, 0.50 vs 0.52):                promote=true, LB +0.0200
```

The first is Welch behaving **correctly** — a large, clean separation genuinely is significant at
n=5. FR-037a's premise (that small n cannot clear the bound) is mathematically false. The second is a
genuinely degenerate case: with zero within-arm variance the bound collapses to the raw difference, so any
positive gap promotes.

`promotion-gate.ts` must stay byte-identical, so this is **pinned as observed behaviour and raised**,
not silently fixed and not papered over by weakening the test.

**The actual backstop is FR-037b, and it holds.** `src/suggest/executor.ts:643` throws
`NEEDS_HUMAN` for `arm-promotion` **before any autonomy check**, so a `promote = true` files a pending
suggestion and never moves routing. Pinned by T030 across autonomy levels 0–5, and mutation-verified:
replacing the throw with `buildAgentSteps` → `Tests 1 failed | 36 passed (37)`; restore byte-identical.

**On the live corpus this is not currently reachable**: magma var 0.1328, multihop-iter var 0.1467,
3 distinct outcome values each — Monday's verdict is `promote: false, LB -0.188`, an honest null.

## 8. `npm run typecheck` DOES NOT TYPECHECK THE TESTS — found by this work

`tsconfig.json` line 27: `"exclude": ["node_modules", "dist", "test", "references"]`. So
`npm run typecheck` (`tsc --noEmit`) never looks at `test/**`. Consequence, hit twice today:

- The F1-era FR-039 test passed a verdict literal with only 5 of `HumanPromotionVerdict`'s 9 fields.
  It compiled (never checked) and passed (nothing read the missing fields yet). The moment FR-039
  started reading `challengerMean`, it died with
  `TypeError: Cannot read properties of undefined (reading 'toFixed')`.
- My first draft of the FR-038 wiring test used `challengerN`/`incumbentN`/`lowerBound` — three wrong
  names — behind an `as never` cast, and produced the same crash.

**This matters beyond a broken fixture**: a fixture that omits fields makes a test green against a
feature that reads them, and `npm run typecheck` exiting 0 is not evidence to the contrary.

Fix applied: both fixtures are now DERIVED from the real gate via a `verdictFor()` helper that calls
`humanOutcomePromotion(...)`. The fixture is the production shape by construction, so it cannot drift.
The remaining exposure (test/ is unchecked) is recorded for John rather than fixed here — changing the
build's typecheck scope is out of this feature's blast radius and would surface unrelated errors.
